Sailing Frog's Leap — Next Build Plan

Three Objectives

These are the next three LEAP development goals, in the order we intend to tackle them. The first two extend the machine we already built. The third begins defining how Leapers use the machine with each other in the real world.

→

Why These Three Belong Together

Finish the operating loop first, then expose the social value of the system.

These are not three unrelated features. They complete one progression. First, LEAP Checks need a clean life cycle. Second, new members need a clean way to enter that life cycle. Third, once the system reliably creates and records membership history, that history should become useful when Leapers meet each other.

Reliable issuance → clean intake → visible shared identity
Strategic conclusion Build the infrastructure in the same order that a member experiences it. Make LEAP dependable first, make joining easy second, and only then turn the record into a social identity that members can share face-to-face.
1

30-Day Check Issuance

Make expiration part of every new LEAP Check by design.

Crew Record and Ledger History already understand an XRPL Check's actual Expiration field. The missing piece is the issuance side: Xaman's normal Create Check screen does not expose an obvious expiration control.

Manager tool → Create LEAP Check → 30-day expiration automatically added → Xaman signs → Check goes on-ledger
Goal Build a simple LEAP Check creation flow that automatically sets expiration to 30 days while still using Xaman to sign the transaction.
  • Destination wallet
  • 1 LEAP SendMax
  • Canonical public memo
  • Expiration = 30 days from creation
  • Xaman remains the signing wallet
Why first Every later workflow depends on issuing LEAP cleanly. A 30-day expiration keeps the distributor account from accumulating open Checks indefinitely and makes the Checkbook's countdown and cleanup states operationally meaningful.
Done when Rick can create a canonical LEAP Check from one simple manager flow, the transaction already contains the 30-day expiration and memo, and Xaman is used only to review and sign it.
2

Join → Waiting for LEAP

Replace Instagram DM with a direct public-address submission.

Step 3 of join.html should stop asking a new member to send the public XRPL address through Instagram. Instead, the page should provide a text box and Submit button.

Join page → submit public XRPL address → small persistent queue → Waiting for LEAP → Rick issues Check
Minimal storage Store only what the workflow needs: XRPL public address, submission timestamp, and status.

The likely implementation is the existing Cloudflare Worker plus a very small persistent store. Ledger History can then show a manager-side Waiting for LEAP queue.

Once an official outstanding LEAP Check exists for that destination, the manager view can eventually recognize that the person has moved out of the intake queue and into the pending-Check stage.

Why second Today the process leaves the website and depends on an Instagram DM. Bringing the public XRPL address submission into the LEAP site removes ambiguity, reduces manual searching, and gives the manager a visible work queue.
Done when A prospective member can submit a valid public XRPL address on the Join page, Rick can see it under Waiting for LEAP, and issuing a Check moves that person naturally into the existing Check workflow.
3

Crew Profile / QR Identity

Turn the permanent LEAP record into something Leapers can use when they meet each other.

The mental model is the military ribbon rack: a fast visual read of where someone has been, what they have done, and how they fit into the crew.

This is not another administrative feature. It is the social layer of LEAP. A Leaper meeting another Leaper in a marina, anchorage, event, or port should be able to exchange identities in seconds and immediately see the other person's LEAP story.

Share My Crew Profile Shows my personal QR code so another Leaper can scan me.
Get Crew Profile Opens the phone camera / QR scanner so I can scan another Leaper.
Leaper A: Share My Crew Profile
↓
QR code
↓
Leaper B: Get Crew Profile / scan
↓
Live XRPL Crew Profile opens

What the scanned profile should show

  • Current rank — Deckhand, Bosun, Quartermaster, First Mate, or Master Of The Leap
  • Current LEAP balance
  • Badges
  • Events
  • Challenges
  • Permanent XRPL history behind those recognitions
Important distinction Leaper Card is the member's own portable identity view. Crew Profile is the profile another person sees after scanning. We may ultimately use one page for both jobs, but the concepts are different.
Preferred QR design The QR should probably contain a website URL carrying the member's public XRPL address, rather than only the raw address. That lets an ordinary phone camera open the Crew Profile directly without requiring a special LEAP app.
Still abstract / to design We have not yet decided the final page name, visual language, ribbon/pennant system, exact QR URL format, privacy/display options, or whether the member can choose a public nickname or call sign. These are intentionally open. The purpose of this document is to preserve the concept before implementation begins.

Real-world use case

Two Leapers meet in a marina. One says, “You hold LEAP?” The other opens their profile and shows the QR. After the scan, the other person can immediately see that this is a Bosun who earned specific badges, completed certain challenges, or shared an event with Sailing Frog's Leap. The ledger record becomes a conversation starter and a visible history of belonging.

Why this matters LEAP stops being only a membership token and becomes a shared social identity. The permanent record is not merely stored — it becomes useful when members meet each other.
Why third The QR/profile idea is powerful precisely because it does not invent a new record. It reveals the record that already exists. By waiting until issuance and intake are dependable, the social layer can remain simple: scan a public address, query XRPL, and display the member's real LEAP history.
Done when Any Leaper can tap Share My Crew Profile to show a QR code, another Leaper can tap Get Crew Profile to scan it, and the resulting page immediately shows the scanned member's current rank and permanent LEAP history.

The Build Order

The sequence is deliberate. Each step removes friction from the step that follows it.

  1. 30-day Check issuance: make LEAP distribution operationally clean.
  2. Join → Waiting for LEAP: make entry into that distribution system simple and visible.
  3. Crew Profile / QR identity: turn the resulting permanent record into something Leapers can use with each other.

The end state is a complete loop: someone joins, receives LEAP, builds a permanent record, and can later carry that record into the real world as a recognizable crew identity.
