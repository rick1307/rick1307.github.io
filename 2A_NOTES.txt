Purpose
- Establish one shared Community Registry.
- Keep SFL and ZHR defined in one place.
- Make Owner/backend pages resolve community identity from that same registry.
- Preserve the existing public-facing community configuration behavior.

Authoritative registry
- js/communityConfig.js

What now comes from the registry
- Community name
- Public/config ID
- Backend ID
- Aliases
- LEAP namespace
- Community Operating Wallet
- Directory status/description
- Existing public-facing configuration (branding, language, ranks, badges, theme, imagery)

Pages converted to the registry
- communities.html
- viewCommunity.html
- viewCommunityTokenomics.html
- viewCommunityRecognition.html
- viewCommunityLibrary.html
- setup.html

Not part of 2A
- Publishing/provisioning a new community
- Owner vs Operator field permissions
- Persistent edits
- Checkbook/Chat feature refactors

No new community is created by this patch. It changes where existing pages get community truth.
